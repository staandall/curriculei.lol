# Revenue-Centric Product Design (curriculei.lol)

Adapted summary. Original work: https://github.com/heliocosta-dev/revenue-centric-design (134 principles — respect license and attribution; do not copy it verbatim; the source forbids use for gambling/betting).

## Rules
1. Link every decision to a user outcome AND a measurable business metric.
2. Define user + use case before writing value proposition copy.
3. Show value before asking for payment or extra personal data (free ATS analysis first).
4. One obvious primary action per screen; secondary actions recede.
5. Remove fields/steps that don't improve quality, security or compliance.
6. Show price and credit cost before the user commits.
7. Offer upgrade at the moment of value or a real limit — never as an interruption trick.
8. Retention comes from recurring value, not notifications or lock-in.
9. Proof proportional to the claim. Never invent testimonials, metrics or results.
10. Measure: activation, time-to-value, real resume improvement, recurring use, conversion, refunds, retention.

## Guardrails
- Free ATS analysis explains criteria and limits.
- ATS score is a diagnosis, never a promise of interview/job.
- Credit debit is visible, idempotent, refunded on technical failure.
- Free/paid line never hides essential information.
- Application automation needs human review and consent.
- Forbidden: fake urgency, fabricated social proof, dark patterns, misleading prices.

## Decision output format
Problem/segment · expected value · mechanism + business metric · evidence or hypothesis · risks/trade-offs · smallest validation test.
